# 네이버 블로그 글 작성

## 개요

API가 아니라 Playwright MCP 브라우저 도구로 실제 네이버 블로그 웹 에디터를 직접
조작하여, 주제를 발행(또는 임시저장) 상태의 네이버 블로그 글로 완성한다. 모든
단계는 눈에 보이는 브라우저 동작(`browser_navigate`, `browser_snapshot`,
`browser_take_screenshot`, `browser_click`, `browser_type` 등)으로 수행되어
사용자가 화면에서 진행 상황을 볼 수 있으며, 주요 단계마다 스크린샷을
`outputs/playwright/<topic-slug>/` 아래에 저장한다.

## 작업 순서

### 1단계: 트리거 및 네이버 블로그 접속

사용자가 "블로그 글 작성" 또는 이에 준하는 네이버 블로그 글 작성/게시 요청을
하면, `browser_navigate`로 네이버 블로그(`https://blog.naver.com`)에 접속한 뒤,
`browser_snapshot`/`browser_take_screenshot`으로 로그인 상태를 확인한다
(헤더의 닉네임/프로필 메뉴 유무 또는 로그인 안내 여부로 판단). 스크린샷은
`outputs/playwright/<topic-slug>/01-login-check.png`에 저장한다 (주제를 아직
모르는 3단계 이전에는 임시 슬러그를 써도 되며, 나중에 확정된 슬러그로
옮기거나 `outputs/playwright/naver-blog-session/` 같은 임시 폴더를 써도 된다).

**로그인되어 있지 않다면: 작업을 멈추고 사용자에게 브라우저에서 직접 로그인해
달라고 요청한다.** 네이버 아이디, 비밀번호를 입력하거나 2단계 인증/OTP 절차를
대신 완료하는 행위는 절대 하지 않는다 — 이는 선호가 아니라 반드시 지켜야 할
경계선이다. 사용자가 로그인 및 계정 확인 완료를 명시적으로 확인해줄 때까지
기다린 뒤 다음 단계로 진행한다.

### 2단계: 주제 질문

사용자가 로그인 완료를 확인해주면, 블로그 글의 주제를 물어본다 (그리고 빠진
정보만 추가로 질문한다: 사용자가 네이버 블로그를 여러 개 운영 중이라면 대상
블로그, 원하는 톤/분량 — 기본값: 표준 분량의 정보성 글).

### 3단계: 템플릿 검색 및 추천

사용자가 주제를 알려주면, `browser_navigate`/`browser_snapshot`을 이용해
네이버 블로그(예: 네이버 블로그 검색이나 에디터의 "템플릿" 패널)에서 주제에 맞는
템플릿이나 기존 글 구성을 검색한다. 후보들을 스크린샷으로 저장한다
(`outputs/playwright/<topic-slug>/02-templates.png`). 짧은 목록(1~3개)을
한 줄 근거와 함께 사용자에게 제시하고 하나를 추천한다. **글 작성을 시작하기
전에 사용자가 템플릿을 승인할 때까지 기다린다.**

### 4단계: 조사 및 본문 작성

템플릿이 승인되면, 주제를 조사하고(WebSearch/WebFetch 및/또는 네이버 블로그/
네이버 검색으로 최신 맥락 확보) 2026년 네이버 블로그 콘텐츠 트렌드에 맞게 글
제목과 본문을 작성한다:

- 짧은 문단(2~4줄)과 잦은 줄바꿈으로 구성된 대화체·1인칭 톤 — 네이버의
  모바일 우선 읽기 패턴에 맞추며, 빽빽한 텍스트 블록은 피한다.
- 첫 2~3줄에 명확한 훅(많은 독자가 검색 미리보기에서 이 부분만 봄), 이어
  짧은 도입부, 소제목이 달린 번호/불릿 섹션, 마지막에 간결한 마무리나
  콜투액션.
- 네이버 특유의 요소: 시각적 구분을 위해 절제된 이모지 사용, 핵심 문구
  볼드 처리, 에디터에서 이미지 삽입이 가능한 섹션 사이 사진/이미지 자리.
- 마지막에 주제의 핵심 키워드에 맞는 `#태그` 목록 포함(네이버 검색/블로그
  노출에 도움), 사용자가 달리 요청하지 않는 한 주제에 맞는 전체 분량 유지
  (보통 본문 1,500~3,000자).

사실을 지어내지 않는다 — 실제 조사한 내용만 사용한다.

### 5단계: 에디터 작성, 임시저장, 사용자 승인

네이버 블로그 에디터(글쓰기)를 연다. 해당 탭에서:

1. 제목 입력란을 클릭하고 제목을 입력한다.
2. 본문 영역을 클릭하고 도입부/훅을 입력한다.
3. 소제목, 문단, 불릿 목록, 태그 섹션 등 블록 단위로
   `browser_click`/`browser_type`을 이용해 계속 작성하며, 각 주요 블록
   작성 후 `browser_snapshot`이나 스크린샷으로 제대로 반영됐는지 확인한다.
4. 태그 입력 필드에 에디터 UI에 맞게 쉼표 또는 Enter로 구분해 태그를 입력한다.

**`browser_type` 액션의 텍스트 값에는 항상 직접 입력한 한글 문자 그대로를
전달한다.** 한글 음절을 `\uXXXX` 이스케이프로 손수 계산해서 만들지 않는다 —
수동 코드포인트 계산은 오류가 매우 잦고 얼핏 비슷해 보이지만 틀린 글자를
조용히 만들어낼 수 있다. 도구/JSON 계층이 인코딩을 자동으로 처리하도록 둔다.

다음 단계로 넘어가기 전에 작성한 각 구역을 스크린샷/스냅샷으로 확대해
실제 렌더링된 텍스트를 확인해 교정한다 — 이런 오류는 언뜻 보면 맞아 보이고
자세히 봐야만 드러난다. 오타를 고칠 때는 단어 하나만 고치려 하지 말고 해당
줄/문단 전체를 선택해서 다시 입력한다.

임시저장을 클릭한다 — 발행은 아직 클릭하지 않는다. 임시저장 상태를 스크린샷
한다(`outputs/playwright/<topic-slug>/03-draft-saved.png`). 사용자에게
보고한다: 작성한 제목과 구역들을 요약하고, 글이 임시저장(비공개) 상태임을
확인시키며, 발행 전에 검토 및 승인을 요청한다.

### 6단계: 발행 및 글 페이지 열기

발행은 명시적 허가가 필요한 행위다 — 진행하기 전에 반드시 사용자의 명확한
승인을 기다린다.

1. 승인을 받으면 필요 시 임시저장 글을 다시 열고 발행을 클릭해 발행
   대화상자를 연다.
2. 전체공개(또는 사용자가 요청한 공개 범위)를 확인/선택한 뒤 확인/발행
   버튼을 클릭한다.
3. 결과 확인 화면을 스크린샷 한다
   (`outputs/playwright/<topic-slug>/04-published.png`).
4. 발행된 글 URL로 이동해 최종 스크린샷을 찍고
   (`outputs/playwright/<topic-slug>/05-final-post.png`), 제목, 공개 범위,
   URL을 사용자에게 보고해 직접 열어볼 수 있게 한다.

### 공통 사항: 화면에 보이는 스크린샷 기록

위 모든 단계는 Playwright MCP 도구로 수행하여 매 단계마다 진행 상황이
화면에 보이도록 해야 한다 — 절대 보이지 않게(headless) 동작하거나 스냅샷/
스크린샷 확인 지점을 건너뛰지 않는다. 이 스킬이 생성하는 모든 스크린샷은
`outputs/playwright/<topic-slug>/` 아래에 저장한다(폴더가 없으면 생성),
이 프로젝트의 규칙상 Playwright MCP의 모든 산출물은 `outputs/playwright/`
아래에 저장되어야 한다.

## 참고 사항

- 사용자가 아무리 명확하게 요청하더라도 네이버 로그인 자격 증명, OTP 코드를
  대신 입력하거나 인증 절차를 대신 완료하지 않는다 — 항상 사용자가 직접
  브라우저 탭에서 로그인하도록 안내한다.
- 이 작업을 위해 연 탭은 직접 정리한다: 사용자가 열어두길 원하지 않는 한,
  작업이 끝나면 닫는다.
