# 티스토리 글 작성

## 개요

API가 아니라 claude-in-chrome 브라우저 확장 프로그램으로 실제 티스토리 웹 에디터를
직접 조작하여, 주제를 발행(또는 임시저장) 상태의 티스토리 글로 완성한다.

## 작업 순서

### 1단계: 범위 확인

빠진 정보만 질문한다:
- 주제
- 사용자가 티스토리 블로그를 여러 개 운영 중이라면 대상 블로그
- 원하는 톤/분량 (기본값: 표준 분량의 정보성 블로그 글)

### 2단계: 브라우저 도구 로드

`claude-in-chrome` 스킬을 먼저 호출한 뒤, 해당 스킬의 안내에 따라
`mcp__claude-in-chrome__*` 도구를 호출하기 전에 ToolSearch
(`select:mcp__claude-in-chrome__tabs_context_mcp,...`)로 핵심 도구 세트를 로드한다.

### 3단계: 자료 조사

WebSearch/WebFetch 및/또는 claude-in-chrome(예: 구글 뉴스 검색)을 이용해 주제에 대한
최신의 정확한 정보를 수집한다. 출처를 기록해두되, 티스토리 글은 리포트처럼 정식
참고자료 목록을 요구하지는 않는다.

### 4단계: 티스토리 접속 및 로그인 확인

사용자의 티스토리(또는 `https://www.tistory.com`)로 이동해 로그인 여부를 확인한다
(헤더의 아바타/닉네임 유무 또는 로그인 안내 여부로 판단).

**로그인되어 있지 않다면: 작업을 멈추고 사용자에게 브라우저에서 직접 로그인해
달라고 요청한다.** 비밀번호, 카카오 계정 자격 증명을 입력하거나 로그인 절차를
대신 완료하는 행위는 절대 하지 않는다 — 이는 선호가 아니라 반드시 지켜야 할
경계선이다. 사용자가 로그인 완료를 확인해줄 때까지 기다린 뒤 다음 단계로
진행한다.

### 5단계: 글쓰기 화면에서 작성

글쓰기 버튼을 클릭한다 (새 탭에서 `.../manage/newpost`가 열림). 이후 해당 탭에서:

1. 제목 입력란을 클릭하고 제목을 입력한다.
2. 본문 영역을 클릭하고 도입부 문단을 입력한다.
3. 이어지는 블록마다: 소제목 앞에는 빈 줄을 위해 `computer` 도구의 `key`
   액션으로 `Return Return`을, 그 아래 문단 앞에는 `Return`을 입력한다. 목록형
   내용은 하나의 `type` 호출 안에서 `"- "`로 시작하는 줄들을 `\n`으로 이어
   작성하면 된다.
4. 하단의 `#태그입력` 필드에 태그를 쉼표로 구분해 입력한 뒤 `Return`을 누른다.
5. 클릭/입력/스크린샷을 한 번의 왕복으로 묶으려면 `browser_batch`를 우선
   사용한다.

**중요: `type` 액션의 `text` 값에는 항상 직접 입력한 한글 문자 그대로를
전달한다.** 한글 음절을 `\uXXXX` 이스케이프로 손수 계산해서 만들지 않는다 —
수동 코드포인트 계산은 오류가 매우 잦고, 얼핏 비슷해 보이지만 틀린 글자를
조용히 만들어낸다 (예: 아셴→아션, 갖췄을→갖춤을, 뮤직→럮미직, 도넛→도넫). 만약
어떤 도구 계층에서 JSON 이스케이프가 필요하다면, 그건 JSON 인코더가 자동으로
처리하도록 둔다.

### 6단계: 교정

작성한 각 구역을 확대(zoom)해서 실제 렌더링된 텍스트를 확인한다 — 이런 오류는
언뜻 보면 맞아 보이고 자세히 봐야만 드러난다.

오타를 고칠 때는 **문단/줄 전체를 트리플 클릭해서 전부 다시 입력**한다 —
더블 클릭은 쓰지 않는다. 띄어쓰기가 없는 한글 텍스트에서 더블 클릭은 하나의
연속된 어절 전체(단어+뒤따르는 공백)를 선택하므로, 고칠 단어만 다시 입력하면
주변 텍스트나 공백이 조용히 사라질 수 있다.

### 7단계: 임시저장

임시저장을 클릭한다. 완료/발행은 아직 클릭하지 않는다.

사용자에게 보고한다: 작성한 구역들을 요약하고, 글이 임시저장(비공개) 상태임을
확인시키며, 발행 전에 검토 및 승인을 요청한다.

### 8단계: 발행 (명시적 승인 후에만)

발행(공개 또는 보호 공개)은 명시적 허가가 필요한 행위다 — 최종 확인 버튼을
누르기 전에 반드시 사용자로부터 구체적인 공개 범위(공개 / 공개(보호) / 비공개)에
대한 승인을 받는다. 사용자가 명시적으로 요청한 비공개 저장은 별도의 추가 확인이
필요 없다.

1. 완료를 클릭해 발행 대화상자를 연다.
2. 스크린샷에서 확인 버튼이 오른쪽 끝에서 잘려 보인다면, 브라우저 창이
   대화상자 레이아웃보다 좁은 것이다 — 해당 탭에 `resize_window`를 호출한 뒤
   (예: 1280x900) 다시 스크린샷을 찍는다.
3. 요청받은 공개 범위 라디오 버튼을 선택한 뒤 확인 버튼을 클릭한다 (선택에 따라
   버튼 라벨이 "공개 발행" / "비공개 저장" 등으로 바뀐다).
4. 글 관리(글 목록) 페이지에서 제목, 공개 범위, 시각, URL을 사용자에게
   최종 확인시켜준다.

## 참고 사항

- 사용자가 아무리 명확하게 요청하더라도 티스토리나 카카오 로그인 자격 증명을
  대신 입력하지 않는다 — 항상 사용자가 직접 브라우저 탭에서 로그인하도록
  안내한다.
- 이 작업을 위해 연 탭은 직접 정리한다: 사용자가 열어두길 원하지 않는 한, 작업이
  끝나면 닫는다.
